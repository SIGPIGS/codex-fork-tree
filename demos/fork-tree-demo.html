Layout E drops the frames. It is an outline of sessions; under each forked session, an indented line shows the turn and prompt it forked after. A right-aligned column shows each session's own turns and age. The path from the root down to the focus session is drawn in the accent color. Click the terminal or just start typing: j/k move, h/l fold, Enter opens the transcript, = switches density, v compares with the framed layout D, and ? lists every key. All sessions and prompts are made-up examples.

E · Outline + fork info no frames

Each session is one row, indented under the session it was forked from. The line right below a forked session says where it split off: turn 9 · “the last shared prompt”. Every row spans the full pane width, so +N · age lines up in one column.

  • ▣ (bold green) marks a session that has forks; ○ marks one that doesn't
  • Focus: ● and the title in accent orange, and the tree lines leading down to it are drawn in accent too
  • Comfortable density adds a guide-only row between siblings; = switches to compact
  • Costs 2 columns per nesting level, with no right-hand border

Decisions for you

  1. Fork info line: turn 9 · “prompt” under every forked session (shown), or only when it differs from the previous sibling's?
  2. Focus: accent path plus accent title (shown). Would you also like a full-row tint on the focus row when the cursor is elsewhere?
  3. Sessions with forks off the focus path start folded (see “Rewrite compaction ▸ +1”). Should they start expanded?
  4. Inferred forks appear with dashed connectors after verification. Should they stay hidden until you confirm them with x?
